Architecture

One WebSocket. Five local processes. No round trip leaves your laptop.

The browser never talks to the database or the model directly. Every request goes through FastAPI, which owns all business logic and only exposes a documented WebSocket protocol to the client.

What's actually built

Not a chat demo wearing a microphone.

Every item below is wired end to end and covered by the test suite, not aspirational bullet points.

Tool calling

Typed tools, not free-form code

Eight tools (booking, cancellation, lookup, knowledge search, escalation), each with a Pydantic schema, validation, and structured errors the model can recover from.

Structured state

State lives in Postgres, not a prompt

Customer, intent, and appointment state persist as real rows. Context sent to the model is windowed and summarized, not the whole transcript every turn.

Barge-in

Interruption that actually interrupts

Each turn runs as a cancellable task. Real speech mid-response cancels the in-flight turn, rolls back its writes, and the client stops audio already playing.

Observability

Every call gets a debug timeline

Tool calls, latencies, and a structured summary are persisted per conversation, with a debug page that replays the whole call as an event log.

Engineering notes

Live-tested against the real stack, not just mocks.

Three bugs only showed up when this ran against a real running Ollama and a real Postgres connection: exactly the kind of thing a mocked test suite can't catch. All three are fixed and re-verified live.

Incident 01async/greenlet

Cancelling a turn crashed later queries

Two turns sharing one DB session meant cancelling an in-flight task under barge-in corrupted SQLAlchemy's async bridge.

Fix: every turn now opens and closes its own session, cancellation-safe by construction.

Incident 02prompt format

The model narrated its own role out loud

Tool results sent as a "system" message confused the chat template into echoing a literal "assistant" into replies, which Piper would have spoken aloud.

Fix: tool results are now sent as role "tool", matching the template's expectations.

Incident 03race condition

A finished turn interrupted itself

A fast client could react to the final "listening" frame before the server's trailing commit finished, making a done turn look still in-flight.

Fix: the commit now happens before the final state frame is sent, not after.
